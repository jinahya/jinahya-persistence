= Test cases and scenarios
:toc:
:toclevels: 2

The one checklist for the three encryption modules. Every scenario the modules must behave the same on has a row
here, and every row names the test method which covers it in each module. An empty cell is a gap; `n/a` is a case
which cannot apply to that module, with the reason.

This document is maintained by hand. The rule is simple: a test method is added or renamed together with its row,
and a review of any of the three modules reads the matrix before it reads the code.

== Columns

[cols="1,2,4"]
|===
| Column | Module | What it runs

| `generic`
| `jinahya-persistence-encryption`
| The standard `AttributeConverter` mapping. Its persistence tests run under *both* providers, through the
  `jakarta-ee-11-hibernate-orm` and `jakarta-ee-11-eclipselink` profiles, so one cell here means two runs. Tests
  named `Hibernate*_Test` are excluded on the EclipseLink profile.

| `hibernate`
| `jinahya-persistence-encryption-hibernate`
| `@Encrypted`, a `UserType` over the generic converters' bytes. Hibernate ORM only.

| `eclipselink`
| `jinahya-persistence-encryption-eclipselink`
| `@Convert("encrypted")`, a native `Converter` over the generic converters' bytes. EclipseLink only.
|===

Cells name `Class.method`, with the nested class when there is one. Test classes sit in
`com.github.jinahya.persistence.encryption`, `...encryption.hibernate` and `...encryption.eclipselink` under each
module's `src/test/java`.

Closed on 2026-10-16, with the measurements they gave (after a Codex review, which asked for the binary search in
the recorder and its positive control, the split of the two in-place mutations with distinct replacement values, the
native NULL checks, and the measured `@Mutable` array):

* C08 on `hibernate`: without `@DynamicUpdate` every column is rewritten, and the unchanged plaintext encrypted once
  more.
* C10 on `generic`: a bulk `UPDATE` parameter goes through the converter on both providers.
* C14, C16, C17 on `generic`: a primitive round-trips through its wrapper's converter on both providers; an in-place
  change of an array or a `Date` is detected on Hibernate ORM and not on EclipseLink, where a converted mapping is
  immutable unless `@Mutable`.
* C18 on both vendor modules, C23 on `eclipselink`, C24 everywhere; P-E01 on `generic`.
* P-E02 on `eclipselink`, the `@Mutable` array: detected in place, and rewritten on every flush, a plain read
  included. It lives on its own fixture, `MutableArrayEntity`, because it bumps the version of every flush of its
  entity, which broke the shared fixture's read and unrelated-change tests when it was tried there.
* P-H02 and P-H03 on `generic`: the standard converter works through a stateless session, and leaves the plaintext
  in the second-level cache. That last one is the measured counterpart of the Hibernate module's cache test.

Closed on 2026-10-16, second pass, after a review of the three modules against this matrix (C26 to C39, P-H05):

* C26, C27, C29, C30, C31, C33, C34, C35 on all three: measured as the contract says.
* C32: the standard converter already converted a literal on both providers; `@Encrypted` did *not*, and wrote the
  literal's own bytes into the column, until the type exposed its converter as Hibernate ORM's value converter.
* C36, C37, C39: Hibernate ORM's default of 255, the lost length of a temporal attribute on the standard mapping,
  and EclipseLink's platform type with no length, all documented in the READMEs as constraints.
* C38: both adapters refuse what a randomized ciphertext cannot be; the generic path is refused by the provider.
* C21, C22: a class-named service is one instance; none or two named fails, measured through a class loader of the
  test's own.
* The generic module's in-memory databases are named and kept open: C35 showed that an unnamed one is private to
  each connection.

== Rules

* A new scenario gets the next free id in its section and a cell in every column, even if the cell is a gap.
* A test method covers one row, or names the rows it covers in its `@DisplayName`. A row covered by half of a method
  says so in the cell, as C07 does.
* `n/a` always carries its reason. "Not written yet" is a gap, never `n/a`.
* The three `SecretEntity` and `AllTypesEntity` fixtures stay shape-equal: a field added to one is added to the others
  in the same change, or the fixture row above says why not.
* When a provider behaves differently on a contract scenario, the cell says what is asserted, as C16 does, and the
  difference is recorded in `VENDORS.adoc`.
